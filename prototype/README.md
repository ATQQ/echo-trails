# 需求面板原型

直接用浏览器打开 `requirements-panel.html`。文件自带样式、脚本和 SVG 图标，不依赖 CDN 或开发服务器。用于确认 PC Web、Tauri 桌面客户端和手机端的布局及交互。

## 当前完成的适配

- 与应用一致使用 480px 作为手机/桌面布局断点；480–999px 使用紧凑导航，避免桌面客户端最小 640px 窗口内容拥挤。
- 手机导航与内容预留安全区；支持 `--safe-area-top`、`--safe-area-bottom`，独立预览默认取 CSS `env()`。手机表单使用 16px 字号避免 iOS 聚焦缩放。
- 主内容在容器内滚动，弹窗表单单独滚动；使用 Visual Viewport 可见高度适配软键盘，并保留表单操作区。
- 识别 Tauri 桌面环境后预留 32px Overlay 标题栏空间。独立预览包含拖拽区域标记，实际窗口拖动需由应用原有外壳提供。
- 数据是独立 localStorage 演示数据，没有跨端同步，也没有读写现有待办数据。页面不显示“已同步”。

## 正式接入现有应用

1. 将原型转换成 `packages/app` 内的 Vue 3 模块，从“发现”增加需求面板入口，保留现有 `/todo` 四象限待办。Web 和原生端共用组件、类型和服务层。
2. 复用现有 `App.vue`、`SideNav` 和 `useResponsive`。桌面端保留全局侧栏，模块导航移为内容区顶部页签，不叠加原型的固定侧栏；手机模块使用四栏底部导航并隐藏该路由的全局 FooterNav，避免两层底栏。桌面标题栏由 App.vue 统一提供。
3. 表单和删除确认等所有弹窗状态必须使用 `@/lib/router` 的 `preventBack`，使 Android 返回键和浏览器返回优先关闭最上层弹窗。独立 HTML 的 Escape 和焦点管理仅用于演示，不能当作原生返回键接入。
4. 页面按当前应用的主容器滚动规则工作；使用现有安全区变量。无需给新模块额外增加 JNI 方法或 native 权限。
5. 新增项目、灵感和任务的统一服务接口，继续通过 `isLocalMode()` 分流：服务端模式使用现有鉴权下的 Hono/Mongoose，本地模式使用 Tauri Rust 命令和现有本地数据库。浏览器只走服务端模式；Tauri 支持两种模式。
6. 现有 todo 接口尚无项目关联和百分比字段，不能直接把原型字段提交给当前接口。落地时同时实现服务端与本地端的字段、持久化及兼容处理；缺失字段提供默认值，保留旧待办数据。原型 localStorage 不作为正式数据库，也不自动导入真实账号。

## 验证边界

浏览器检查可覆盖响应式布局、模拟安全区和标题栏、增删改与刷新保存。正式接入后仍需在实际 Tauri 桌面窗口及 Android/iOS 客户端验证系统返回、软键盘、安全区和数据库读写；模拟环境不能确认原生行为。
